Compliance Traceability Report

A second, narrower run against the same CI Connect deployment: only the 21 CFR Part 11 example extension that ships with VIP, joined against that example’s controls.toml. The Compliance Traceability section is the point — every control, the scenarios that verify it, their outcome, and the timestamp each check ran.

The four Workbench and Package Manager controls report as gaps here, and that is worth reading rather than skipping past. This run configures Connect alone, VIP deselects an unconfigured product’s scenarios rather than skipping them, so those scenarios never reach the results file and the controls they carry read as gaps. The suite has the checks; this run did not exercise them. Confirm which products a run covered before you conclude a control has no automated evidence.

The standard example report is a broad smoke run across Connect, Workbench and Package Manager with no control list attached, so it has no such section and its summary counts many more scenarios. The two differ in scope, not in machinery: both are rendered by the same vip report, and any VIP run can carry a matrix by attaching a control list.

Generate your own: run vip scaffold --template 21cfr-part11-validation --output ./my-tests to get a worked controls.toml and tagged scenarios, replace them with your own regulatory mapping, then vip verify --extensions ./my-tests followed by vip report --controls ./my-tests/controls.toml. The same matrix exports to CSV or JSON with vip trace.

Read the matrix carefully. This example uses a nine-control list, seven of them automated across Connect, Workbench and Package Manager. Controls you mark manual or procedural are reported as not verifiable by automated test, which is deliberately distinct from a coverage gap, and a control whose scenario was skipped is reported as covered but not executed. A green matrix evidences the controls you chose to automate, on the deployment you pointed VIP at, at the time it ran. It is not an attestation of compliance.
